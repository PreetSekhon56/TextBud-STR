Rewrite src/index.ts to replace all `require()` calls with ESM `import` statements. The file currently has:

```typescript
import 'dotenv/config';
import { initDb } from './db/schema.js';
// ...
const { seedDevData } = require('../scripts/seed-dev.js');
const { bot } = require('./bot.js');
const { reloadActiveSessions } = require('./handlers/cleaning.js');
```

The `require()` calls were used to guarantee order (initDb before bot loads). With ESM, we need to keep the same ordering guarantee. Since `initDb()` is called synchronously at module top level before any dynamic import, the approach is:

1. Keep the top-level synchronous imports for dotenv and initDb:
```typescript
import 'dotenv/config';
import { initDb } from './db/schema.js';
```

2. Keep `initDb()` call immediately after:
```typescript
initDb();
console.log('Database initialized');
```

3. Replace the require() calls with dynamic `import()` inside the `main()` async function to preserve load ordering:
```typescript
async function main() {
  const { seedDevData } = await import('../scripts/seed-dev.js');
  const { bot } = await import('./bot.js');
  const { reloadActiveSessions } = await import('./handlers/cleaning.js');

  if (process.env.SEED_DB === 'true') {
    seedDevData(process.env.OWNER_TELEGRAM_ID);
  }

  reloadActiveSessions();

  console.log('TextBud bot is running');
  await bot.launch();

  process.once('SIGINT', () => bot.stop('SIGINT'));
  process.once('SIGTERM', () => bot.stop('SIGTERM'));
}

main().catch((err) => {
  console.error('Failed to start TextBud:', err);
  process.exit(1);
});
```

This preserves the ordering guarantee (initDb runs before bot module loads) while eliminating all require() calls.
